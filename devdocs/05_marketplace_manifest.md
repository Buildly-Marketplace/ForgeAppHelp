# Marketplace Manifest (BUILDLY.yaml)

This document describes the `BUILDLY.yaml` manifest file required for Buildly Marketplace submissions.

## Overview

Every Marketplace submission must include a `BUILDLY.yaml` file at the repository root. This file:

1. Provides metadata for the Marketplace listing
2. Defines test commands for validation
3. Specifies required UI hooks for E2E tests
4. Declares screenshot requirements

## File Location

```
your-repo/
├── BUILDLY.yaml    # Required - must be at repo root
├── marketplace/
│   └── screenshots/
│       ├── 01-home.png
│       └── 02-primary-action.png
└── ...
```

## Required Fields

### Identity

```yaml
# Unique identifier (lowercase, hyphens allowed)
id: my-app-template

# Display name for Marketplace
name: My App Template

# Short description (max 160 characters)
description: A brief description of what this template does

# Semantic version
version: 1.0.0
```

### Categorization

```yaml
# Template category
category: starter  # or: integration, component, full-stack

# Discoverable tags
tags:
  - react
  - frontend
  - dashboard
```

### Frontend

Frontend submissions declare which framework they use and where the build
lands. CI reads `build_dir` when assembling the static image, so it must match
what `npm run build` actually writes.

```yaml
frontend:
  # One of: react | vue | angular | svelte | react-native-web | other
  framework: react
  # Vite/React/Vue: dist   Angular: dist/<project-name>
  # CRA: build             Next (static export): out
  build_dir: dist
  # These npm script names are a contract -- ops/startup.sh, the Dockerfile
  # and CI all invoke them. Keep the names when you swap the framework.
  scripts:
    dev: npm run dev
    build: npm run build
    unit: npm test
```

### Author

```yaml
author:
  name: Your Name
  email: you@example.com
  url: https://yoursite.com  # optional
```

### Legal

```yaml
# SPDX license identifier
license: MIT

# Repository URL
repository: https://github.com/org/repo
```

## Test Commands

Define commands that Marketplace CI will run to validate your submission:

```yaml
tests:
  # Docker-first (required for CI)
  docker:
    e2e: ./scripts/test-e2e-docker.sh
    screenshots: ./scripts/screenshots-docker.sh
  
  # Node-first (optional, for local dev)
  node:
    e2e: ./scripts/test-e2e-node.sh
    screenshots: ./scripts/screenshots-node.sh
    unit: npm test
```

### Requirements

- Docker test commands are **required**
- Commands must exit 0 on success, non-zero on failure
- A lockfile (`package-lock.json`) must be committed, so CI installs the same
  dependency tree you built against
- `node_modules/` must **not** be committed

## App Control

Define the single entrypoint for app control:

```yaml
app:
  control: ./ops/startup.sh
  modes:
    - node
    - docker
  commands:
    - start
    - stop
    - restart
    - status
```

## Screenshots

Marketplace listings display screenshots generated by your tests:

```yaml
screenshots:
  directory: marketplace/screenshots
  required:
    - 01-home.png
    - 02-primary-action.png
  generator: ./scripts/screenshots-docker.sh
```

### Screenshot Rules

1. **Naming**: Use numbered prefixes (`01-`, `02-`) for ordering
2. **Format**: PNG required, consistent dimensions (1280x800 recommended)
3. **Content**: Show app in different states
4. **Generation**: Must be auto-generated by Robot tests (not manually created)

### Why Auto-Generated?

- **Accuracy**: Screenshots always match actual app behavior
- **Freshness**: Updated automatically when UI changes
- **Validation**: Proves the app actually works as shown

## UI Hooks

Required `data-testid` attributes for E2E tests:

```yaml
ui_hooks:
  required:
    - app-root          # Main container
    - primary-action    # Primary CTA
    - panel             # Revealed content
```

These hooks ensure tests can reliably find elements regardless of styling changes.

### Adding Hooks to a Component

The attribute name is the same in every framework this template targets --
only the surrounding syntax changes.

```jsx
// React / React Native Web
<main data-testid="app-root">
  <button data-testid="primary-action" onClick={toggle}>Click Me</button>
  {open && <section data-testid="panel">Panel Content</section>}
</main>
```

```html
<!-- Vue -->
<main data-testid="app-root">
  <button data-testid="primary-action" @click="toggle">Click Me</button>
  <section v-if="open" data-testid="panel">Panel Content</section>
</main>
```

```html
<!-- Angular -->
<main data-testid="app-root">
  <button data-testid="primary-action" (click)="toggle()">Click Me</button>
  <section *ngIf="open" data-testid="panel">Panel Content</section>
</main>
```

Render the panel conditionally rather than hiding it with CSS. `smoke.robot`
asserts the panel is not visible before the primary action is clicked, and a
merely-hidden element can still report as present.

## Validation Rules

```yaml
validation:
  tests_must_pass: true       # All E2E tests must pass
  screenshots_required: true  # Required screenshots must exist
  manifest_required: true     # BUILDLY.yaml must be valid
  lockfile_required: true     # package-lock.json must be committed
  ui_hooks_required: true     # Every hook in ui_hooks.required must exist in src/
```

## Complete Example

```yaml
id: forge-fe-template
name: ForgeAppHelp
description: A frontend starter template for Buildly Marketplace submissions
version: 1.0.0
category: starter

tags:
  - template
  - starter
  - frontend
  - react

author:
  name: Buildly Marketplace
  email: marketplace@buildly.io

license: MIT
repository: https://github.com/Buildly-Marketplace/ForgeAppHelp

requirements:
  node: ">=20"
  npm: ">=10"
  docker: ">=20.10"
  python: ">=3.10"   # Robot/Playwright test runner only, not the app

frontend:
  framework: react
  build_dir: dist
  scripts:
    dev: npm run dev
    build: npm run build
    unit: npm test

tests:
  docker:
    e2e: ./scripts/test-e2e-docker.sh
    screenshots: ./scripts/screenshots-docker.sh
  node:
    e2e: ./scripts/test-e2e-node.sh
    screenshots: ./scripts/screenshots-node.sh
    unit: npm test

app:
  control: ./ops/startup.sh
  modes: [node, docker]
  commands: [start, stop, restart, status]

screenshots:
  directory: marketplace/screenshots
  required:
    - 01-home.png
    - 02-primary-action.png
  generator: ./scripts/screenshots-docker.sh

ui_hooks:
  required:
    - app-root
    - primary-action
    - panel

validation:
  tests_must_pass: true
  screenshots_required: true
  manifest_required: true
  lockfile_required: true
  ui_hooks_required: true
```

## Validation

Before submitting, verify your manifest:

```bash
# Run tests
./scripts/test-e2e-docker.sh

# Generate screenshots
./scripts/screenshots-docker.sh

# Check screenshots exist
ls -la marketplace/screenshots/
```

## Common Issues

### "Missing required screenshot"

Run the screenshot generator:
```bash
./scripts/screenshots-docker.sh
```

### "Test command failed"

Check the test output in `artifacts/robot/`:
- `smoke-report.html` - Human-readable report
- `smoke-log.html` - Detailed execution log

### "Invalid BUILDLY.yaml"

Validate YAML syntax:
```bash
python3 -c "import yaml; yaml.safe_load(open('BUILDLY.yaml'))"
```

### "commit a lockfile"

CI installs with `npm ci`, which requires `package-lock.json`. Run `npm install`
once and commit the lockfile it produces.

### "node_modules is committed"

Add `node_modules/` to `.gitignore` and remove it from the index:

```bash
git rm -r --cached node_modules
```

### "MISSING: <hook> (declared in BUILDLY.yaml ui_hooks)"

A `data-testid` listed under `ui_hooks.required` is absent from `src/`. Either
restore the attribute or update `ui_hooks` and the Robot suites together --
they must agree.

### App works with `npm run dev` but the Docker image 404s

`frontend.build_dir` does not match where `npm run build` writes. Check the
output directory your framework uses (Vite `dist`, CRA `build`, Angular
`dist/<project-name>`, Next static export `out`) and set both
`frontend.build_dir` in `BUILDLY.yaml` and the `BUILD_DIR` build arg in
`ops/docker-compose.yml`.
